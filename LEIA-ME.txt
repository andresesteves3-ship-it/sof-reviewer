COMO ATUALIZAR NO GITHUB (repositório sof-reviewer)
  1. Extraia o zip.
  2. Add file > Upload files.
  3. Arraste, de dentro da pasta extraída: index.html, sw.js, manifest.webmanifest, a pasta "ferramentas" e a pasta "icons".
  4. Commit changes. Espere 2 minutos e abra o endereço.
  O endereço continua o mesmo; o app instalado passa a abrir o painel.

ENTRADA: e-mail da Triunfo + senha (mínimo 6 caracteres), com contas criadas no Firebase (Authentication). Veja FIREBASE-PASSO-A-PASSO.txt.
Todos os usuários têm o mesmo nível (MASTER). A senha vale em qualquer computador e pode ser trocada em Meu perfil.
O registro de atividade fica salvo só no computador usado.

LINE UP (0.5.0)
  Lista só os navios PREVISTOS do Geport (sem data de início, não finalizados/cancelados), com ETA e carga, e a situação do prático na Praticagem RJ.
  Geport: favorito "Enviar para o Line Up" (no Geport, Frente de Trabalho > Aquaviária, clique no favorito).
  Praticagem: um ROBÔ no GitHub Actions lê praticagem-rj.com.br a cada 1 hora, mesmo com tudo fechado, e grava dados/praticagem.json (histórico: marcado, cancelado, voltou, alterado, concluído). O Line Up lê esse arquivo e recarrega sozinho a cada 5 minutos.
    "Recarregar Praticagem" = relê o arquivo agora. "Pedir consulta agora" = abre o GitHub para você clicar em Run workflow (leitura na hora; espere ~1 min e recarregue).
  "Solicitar Inspeção": aparece nos navios com prático marcado; pergunta cabeço inicial, cabeço final e guindastes e gera texto p/ WhatsApp (MODELO PROVISÓRIO, ver textoInspecao() no index.html).

COMO ATIVAR O ROBÔ (uma única vez)
  1. No GitHub, repositório sof-reviewer: Add file > Upload files. Suba TUDO desta pasta, inclusive as pastas "scripts", "dados" e ".github" (a pasta .github precisa ir inteira, com workflows/praticagem.yml dentro) e o arquivo package.json.
     Se o upload não aceitar a pasta .github: Add file > Create new file, nome ".github/workflows/praticagem.yml" (digitar a barra cria as pastas), e cole o conteúdo do arquivo.
  2. Settings > Actions > General > Workflow permissions: marque "Read and write permissions" e Save.
  3. Aba Actions > "Robô da Praticagem" > Run workflow (primeira leitura na hora). Se aparecer aviso de habilitar Actions, habilite.
  4. Confira no Line Up: "Praticagem lida pelo robô em ...". Depois disso roda sozinho a cada hora.
  Observações: o repositório do GitHub Pages grátis é público; o arquivo só guarda dados já públicos da Praticagem. O GitHub desliga tarefas agendadas após 60 dias sem atividade no repositório (o robô grava um arquivo por dia, o que mantém atividade). O horário do GitHub pode atrasar alguns minutos.
  Se o site da Praticagem bloquear os servidores do GitHub, o Line Up avisa "a última tentativa falhou"; nesse caso usaremos Cloudflare Worker.
  Dados do Geport e histórico de login continuam só neste computador. Favorito do Geport não usa nem guarda senha.

ROBÔ DO GEPORT (0.6.0)
  O GitHub entra no Geport a cada hora com um usuário/senha guardados como Secrets (não aparecem para ninguém), lê Frente de Trabalho > Aquaviária e grava só os navios PREVISTOS em dados/geport.enc.json CRIPTOGRAFADO (o repositório é público). O Line Up abre esses dados com a chave de acesso (digitada uma vez por computador).
  Ativação:
    1. Subir para o GitHub: scripts/geport.js, package.json (novos/atualizados) e index.html, sw.js. Criar à mão o arquivo .github/workflows/geport.yml (Add file > Create new file), com o conteúdo do geport.yml desta pasta.
    2. Settings > Secrets and variables > Actions > New repository secret, criar três:
         GEPORT_USER  = usuário do Geport
         GEPORT_PASS  = senha do Geport
         LINEUP_KEY   = uma frase-chave inventada (12+ caracteres) que a equipe vai digitar no Line Up
    3. Aba Actions > Robô do Geport > Run workflow. Abrir o job "ler" e conferir a linha "OK: N linhas lidas".
    4. No Line Up, digitar a chave de acesso (card no topo). Pronto: atualiza sozinho a cada hora.
  Se der "FALHOU", o texto do erro aparece no log do job e no Line Up (login recusado, captcha, tabela não apareceu...). O favorito do Geport continua funcionando como alternativa.
  Segurança: use, se a TI permitir, um usuário de integração só de leitura. Troque a senha do Geport que foi colada no chat. Quem trocar a senha do Geport precisa atualizar o Secret GEPORT_PASS.

REQUISIÇÕES / ROBÔ DO OGMO (v0.10.0)
1) No GitHub (repositório sof-reviewer): Settings > Secrets and variables > Actions > New repository secret.
   Crie 3 segredos (VOCÊ digita; não envie senha em chat): OGMO_EMPRESA (250), OGMO_USER (seu login) e OGMO_PASS (sua senha).
   LINEUP_KEY já existe e é a mesma do Line Up.
2) Suba scripts/ogmo.js (Add file > Upload files, pasta scripts) e crie o arquivo .github/workflows/ogmo.yml
   (Add file > Create new file, com esse nome; cole o conteúdo do arquivo do zip).
3) Actions > Robô do OGMO > Run workflow. Depois abra a aba Requisições do painel.
O robô só LÊ (nunca cria, altera ou cancela requisições). Lê hoje e amanhã.

EMITIR PDF DA REQUISIÇÃO E DA9 (aba Requisições)
- Em cada requisição há os botões PDF e DA9 (o DA9 só habilita quando a equipe está escalada).
- O painel pede ao robô (workflow ogmo-emitir.yml); em 1 a 2 minutos o arquivo aparece como link na própria tela.
- Precisa de: scripts/ogmo.js atualizado, .github/workflows/ogmo-emitir.yml criado, os Secrets do OGMO e a chave do GitHub (Actions: Read and write) cadastrada na aba Line Up.
- Os PDFs ficam criptografados no repositório (dados/emissao-*.enc.json) e são apagados depois de 1 dia.

RELATÓRIO OFICIAL (PDF) DE CADA REQUISIÇÃO
- O robô de leitura do OGMO (a cada hora) também clica em "Gera Relatório da Requisição Selecionada" e guarda o PDF, criptografado, em dados/rpdf/.
- Só baixa de novo quando a requisição muda; até 15 novos por rodada (OGMO_PDFS_MAX); OGMO_PDFS=0 desliga.
- O botão PDF do painel abre esse arquivo na hora. Se ainda não existir, o painel gera uma cópia própria.

DA9 (aba Requisições)
- O robô de leitura também baixa o DA9 das requisições já escaladas (dados/da9/, criptografado) e o botão DA9 abre na hora.
- Se ainda não foi baixado, o botão pede ao robô (ogmo-emitir.yml) e o arquivo aparece em 1 a 2 minutos.
- OGMO_DA9=0 desliga o download automático do DA9 (ele traz nome e matrícula dos trabalhadores).
- Segurança do robô: ele bloqueia qualquer botão que inclua, altere, cancele ou duplique requisições; só consulta e baixa relatórios.
